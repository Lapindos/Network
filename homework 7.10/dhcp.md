# Конспект: Протокол DHCP

## 1. Введение
Для работы в сети каждому устройству необходим IP-адрес и дополнительные параметры (маска сети, шлюз, DNS-сервер). Ручная настройка — трудоемкий процесс, чреватый ошибками и дублированием адресов. 
**DHCP (Dynamic Host Configuration Protocol)** — протокол, который автоматизирует процесс конфигурации сетевых интерфейсов и исключает дублирование IP-адресов за счет централизованного управления.

## 2. Прародители DHCP
*   **RARP (Reverse ARP):** Выдавал IP-адрес по MAC-адресу через широковещательный запрос. 
    *   *Минусы:* Требовал сервера в каждом сегменте сети; нельзя было передать дополнительные настройки (маску, шлюз и т.д.).
*   **BOOTP (Bootstrap Protocol):** Создан для бездисковых станций. Позволял передавать дополнительные параметры (адрес TFTP, имя файла загрузки). 
    *   *Плюс:* Появилась поддержка **Relay** (агентов-посредников), что позволило использовать один сервер на несколько сетей. 
    *   *Минус:* Все еще требовалась ручная настройка таблиц.
*   **DHCP:** Является обратно совместимым расширением BOOTP (DHCP-сервер обслуживает клиентов BOOTP, но не наоборот).

## 3. Режимы работы DHCP
DHCP-сервер работает по модели "клиент-сервер" и поддерживает три режима выдачи адресов из заданного пула:
1.  **Ручное назначение:** Жесткая привязка IP-адреса к MAC-адресу. Клиент всегда получает один и тот же заданный администратором IP.
2.  **Автоматическое назначение:** Сервер сам выдает случайный IP из пула, но отдает его клиенту в *постоянное пользование* (навсегда закрепляет за ним при первом обращении).
3.  **Динамическое распределение:** IP-адрес выдается на ограниченное время (**срок аренды**). Если клиент отключается, адрес возвращается в пул и может быть выдан другому.
    *   *Преимущество:* Позволяет обслуживать больше устройств, чем есть свободных IP-адресов (например, 500 мобильных сотрудников могут работать через пул из 64 IP-адресов, если они не находятся в офисе одновременно).

## 4. Архитектура и алгоритм работы
Администратор задает **пул адресов** и **срок аренды** (от нескольких часов для гостевых сетей до нескольких недель для корпоративных).
Так как клиенты ищут сервер широковещательными запросами, сервер должен находиться в той же подсети. Если сервера в подсети нет, используется **Связной DHCP-агент (DHCP Relay Agent)**, который перехватывает запросы и перенаправляет их серверу в другой сети.

### Процесс получения адреса (4 шага):
1.  **DHCP-поиск (Discover):** Клиент отправляет широковещательный запрос при включении (ищет сервер).
2.  **DHCP-предложение (Offer):** Все доступные серверы присылают свои предложения с IP и настройками.
3.  **DHCP-запрос (Request):** Клиент выбирает одно предложение (обычно первое) и отправляет широковещательный запрос с указанием выбранного сервера.
4.  **DHCP-квитанция (Acknowledge):** Выбранный сервер подтверждает аренду. Остальные серверы отменяют свои предложения и возвращают адреса в пулы.

*Примечание:* Клиент пытается продлить аренду заранее. Если сервер недоступен, он ищет другие. При истечении срока аренды без ответа серверов клиент теряет IP-адрес.

## 5. Проблемы динамических адресов и их решения
Постоянная смена IP-адресов узлов создает ряд сложностей:
1.  **Служба DNS:** Обычный DNS не справляется с частой сменой IP. 
    *   *Решение:* Использование динамического DNS (DDNS), интегрированного с DHCP.
2.  **Мониторинг и управление:** Сложно удаленно управлять устройством, если его IP постоянно меняется.
3.  **Безопасность (Firewall):** Сложно настраивать правила фильтрации пакетов.
    *   *Решение для п.2 и п.3:* Отказ от динамики для важных узлов. Серверам, маршрутизаторам и сетевым принтерам назначаются **статические (постоянные) IP-адреса**.
