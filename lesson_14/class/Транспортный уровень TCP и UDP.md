# Транспортный уровень: TCP и UDP

Транспортный уровень — четвёртый в OSI и лежит между приложением и IP в стеке TCP/IP. Он связывает программы на разных узлах. Он режет данные на части и собирает их у получателя, адресует приложения портами и, если это TCP, ставит соединение, следит за доставкой, порядком и потоком.

Единица этого уровня — **TPDU**: сегмент TCP или дейтаграмма UDP. IP кладёт её в пакет, канальный уровень — в кадр. Приложения зовут транспорт через интерфейс сокетов.

## Порты

Порт — 16-битный номер. IP выбирает узел, порт — программу на нём. Запись `192.168.1.3:80` — конкретная программа на конкретном узле.

| Диапазон | Группа |
| --- | --- |
| 0–1023 | общеизвестные |
| 1024–49151 | зарегистрированные |
| 49152–65535 | динамические |

Номера ведёт IANA. Сервер обычно слушает известный порт, клиенту ОС выдаёт временный. У TCP и UDP пространства портов разные.

| Служба | Порт | Транспорт |
| --- | --- | --- |
| FTP, управление | 21 | TCP |
| Telnet | 23 | TCP |
| SMTP | 25 | TCP |
| DNS | 53 | UDP или TCP |
| DHCP | 67 сервер, 68 клиент | UDP |
| TFTP | 69 | UDP |
| HTTP | 80 | TCP |
| SNMP | 161 | обычно UDP |

**Сокет** — это IP и порт. Соединение TCP задают два сокета: клиентский и серверный. Один серверный сокет держит много клиентов. **Мультиплексирование** сваливает потоки разных программ в IP, **демультиплексирование** раздаёт пришедшее обратно по портам. Так на одном адресе живут и FTP, и HTTP.

## UDP

Каждая дейтаграмма UDP везёт отдельное сообщение и сохраняет его границы. Соединения нет: нет подтверждений, повторов, порядка и управления потоком. Если входной буфер переполнен, сообщение просто выбрасывают. Потери, если они важны, обрабатывает само приложение.

Заголовок короткий, соединение устанавливать не надо, поэтому UDP берут для коротких запросов, голоса и видео. Так ходят DNS, DHCP, TFTP и SNMP.

Заголовок занимает **8 байт**, четыре поля по 16 бит: порт отправителя, порт получателя, длина всей дейтаграммы и контрольная сумма. В поле протокола IP у UDP номер **17**. В обычном IPv4-пакете с заголовком 20 байт дейтаграмма UDP не длиннее 65515 байт.

## TCP

TCP везёт надёжный поток байтов в обе стороны. Поток режут на сегменты, получатель склеивает их обратно. Границы отдельных сообщений приложения TCP не хранит.

Надёжность дают номера байтов, контрольная сумма, подтверждения и повтор. Дубликаты отбрасывают, порядок восстанавливают. Если обмен продолжить нельзя, соединение закрывают с ошибкой. TCP берут FTP, HTTP, SMTP и иногда DNS. Это связь двух точек, не широковещание и не группа.

Основной заголовок — **20 байт**, с параметрами — до 60.

| Поле | Зачем |
| --- | --- |
| Порты | какая программа |
| SEQ | номер первого байта данных сегмента |
| ACK | номер следующего байта, которого ещё ждут |
| Длина заголовка | где начинаются данные |
| Флаги | как обрабатывать сегмент |
| Окно | сколько байтов получатель ещё примет |
| Контрольная сумма | ошибка в заголовке или данных |
| Указатель срочности | вместе с флагом URG |
| Параметры | MSS, масштаб окна, SACK, метки времени |

Флаги: **SYN** согласует начальные номера, **ACK** говорит, что поле подтверждения заполнено, **FIN** закрывает свою сторону, **RST** сбрасывает соединение, **PSH** просит отдать данные приложению сразу, **URG** включает указатель срочности.

## Рукопожатие и закрытие

1. Клиент шлёт **SYN** со своим начальным SEQ.
2. Сервер отвечает **SYN+ACK**: свой SEQ и подтверждение SYN клиента.
3. Клиент шлёт **ACK** на SYN сервера. Соединение открыто.

В учебном примере клиент ставит `SEQ=100`, сервер отвечает `SEQ=300, ACK=101`, клиент подтверждает `ACK=301`. Сам SYN занимает один номер.

Обычное закрытие — каждая сторона закрывает своё направление: FIN, ACK, FIN, ACK. Подтверждение и FIN можно склеить. **RST** рвёт соединение сразу.

## Окно, поток и перегрузка

Остановка и ожидание шлют один кусок и ждут ответ. Если подтверждение не пришло до тайм-аута, кусок шлют снова. Так медленно.

**Скользящее окно** разрешает несколько сегментов до подтверждения. Размер окна — в байтах. После ACK окно сдвигается. Кумулятивное `ACK=X` значит: всё, что меньше X, уже принято, следующий ждут байт X. При окне 3000 байт можно отправить два сегмента по 1500. Когда байты 1–3000 на месте, приходит `ACK=3001`. Если кусок потерян, ACK продолжает указывать на дыру. **SACK** отдельно сообщает, какие диапазоны после дыры уже есть.

Отправитель держит неподтверждённые данные для повтора. Тайм-аут **RTO** подстраивают по **RTT** — времени от отправки до ACK. **SRTT** — сглаженная оценка этого времени.

**Управление потоком** бережёт медленного получателя. Он сообщает свободное место буфера окном **RWND**. Нулевое окно останавливает отправителя; тот время от времени проверяет, не открылось ли оно, пробным сегментом.

**Управление перегрузкой** бережёт сеть. Отправитель держит окно **CWND**. В пути одновременно не больше `min(RWND, CWND)`. Сигнал перегрузки — потеря, рост задержки или явная пометка маршрутизатора. Если все сразу уменьшат окна, а потом вместе разгонятся, получается глобальная синхронизация TCP.

| Алгоритм | Идея |
| --- | --- |
| Медленный старт | начать с маленького CWND и быстро растить его по подтверждениям, примерно удваивая за RTT, пока не достигнут порог |
| Предупреждение перегрузки | после порога прибавлять примерно один MSS за RTT |
| Быстрый повтор | три одинаковых ACK — повторить потерянный сегмент, не ждать тайм-аута |
| Быстрое восстановление | ужать окно и продолжить, не падая в самый начало медленного старта |

Если сработал таймер, порог примерно делят пополам, CWND возвращают к стартовому значению и снова идут медленным стартом.

## Сравнение

| | TCP | UDP |
| --- | --- | --- |
| Соединение | нужно | не нужно |
| Данные | поток байтов | отдельные дейтаграммы |
| Подтверждения и повтор | есть | нет |
| Порядок | восстанавливают | не восстанавливают |
| Поток и перегрузка | есть | нет |
| Заголовок | 20–60 байт | 8 байт |
| Накладные расходы | выше | ниже |

`netstat -an` показывает соединения и слушающие порты. `telnet 192.168.1.100 80` проверяет, открывается ли TCP-порт. Для UDP так не проверить.
