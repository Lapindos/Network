# Анализ трафика в Wireshark

Верхняя панель — список кадров: номер, время, адреса, протокол и короткая расшифровка. Средняя раскрывает кадр по уровням: Ethernet, IP, затем TCP или UDP. Нижняя показывает байты. Строка дерева подсвечивает свои байты внизу.

Фильтр `tcp` оставляет сегменты TCP, фильтр `udp` — дейтаграммы UDP. Число внизу окна говорит, сколько пакетов в файле и сколько прошло фильтр. `netstat -an` на самом компьютере показывает соединения и слушающие порты. Открывается ли TCP-порт, проверяют `telnet` на этот порт. Для UDP такой проверки нет.

## Что искать в TCP

В дереве TCP смотрят порты, SEQ, ACK, окно и флаги.

- **SYN** начинает соединение и занимает один номер последовательности.
- **ACK** значит, что поле подтверждения заполнено. Кумулятивный ACK называет следующий байт, которого ещё нет.
- **PSH** просит отдать данные приложению, не копить их.
- **FIN** закрывает свою сторону.
- **RST** сбрасывает соединение.

Рукопожатие — три сегмента: SYN, SYN+ACK, ACK. В учебном разборе клиент может начать с `SEQ=100`, сервер ответить `SEQ=300, ACK=101`, клиент закрыть рукопожатие `ACK=301`.

Окно — сколько байтов отправитель ещё готов принять. Длина сегмента и полезная нагрузка — разные величины: из кадра вычитают заголовки. Пометка unverified checksum значит, что анализатор не проверил сумму при текущих настройках. Для разбора важны порты, флаги и номера, а не содержимое чужого TLS.

## Что искать в UDP

В заголовке четыре поля, всего 8 байт: порт источника, порт получателя, длина и контрольная сумма. Флагов соединения нет. В поле протокола IP у UDP номер 17. Длина включает свой заголовок, остальное — данные. Внутри может лежать DNS, DHCP или QUIC.

Два кадра TCP с разными флагами и один кадр UDP как раз показывают эту разницу: у TCP есть состояние соединения, у UDP — только порты и длина.
